# 项目管理层访谈纪要

## 目标

使用 `assets/附件1：项目管理层访谈纪要.docx` 作为唯一模板源，根据用户提供的企业 BP、现场访谈记录和其他参考资料，结合互联网公开信息核验，生成该项目的管理层访谈纪要。

每个字段都必须标记信息来源。默认输出 Word `.docx`，并采用三重溯源：

- 正文中每个填写段落后追加可见的 `【信息来源】`、`【证据等级】`、`【待核实】`
- 对填写段落添加 Word 批注
- 文末新增 `字段来源标注` 和 `来源清单`

## 工作原则

- 以现场访谈记录为主，BP 和公开信息用于补全与交叉验证。
- 不要把 BP 宣传语原样搬进纪要；要转写为访谈纪要口径。
- 区分 `管理层陈述`、`BP/公司材料`、`公开信息核验`、`第三方报告/估算`、`模型推断`。
- 对未被访谈确认或公开核验的信息标注 `待核实`。
- 对负面舆情、处罚、诉讼、技术权属、财务预测、估值和上市安排保持保守表述。
- 时间、金额、比例、客户、订单、专利、融资、估值、财务数据必须写明口径和截至日期。

## 字段结构

字段索引见 `references/field-map.csv`。核心字段包括：

- 标题、访谈时间、访谈地点
- 参会人员：标的公司、工银投资/工银资本、分行、其他投资机构
- 公司基本情况：历史沿革、团队主要成员背景
- 股东及融资：控股股东、主要股东、前序轮次投资人
- 主营业务：主要产品、商业模式、核心竞争力
- 重大事项：处罚、负面舆情、重大诉讼
- 技术水平：专利、国家部委专项、科技奖项
- 行业概览及竞争情况：行业规模、地位、政策、市场空间、趋势、竞争者
- 主要经营指标及财务数据：资产、收入、利润、现金流、盈亏平衡、预测
- 本轮估值、主要参与方、上市安排
- 其他需要关注的事项

## 工作流

1. 读取资料
   - 用户提供的 BP、现场访谈记录、访谈录音转写、尽调资料、财务报表、行业研究、投资方案等。
   - 模板：`assets/附件1：项目管理层访谈纪要.docx`
   - 字段索引：`references/field-map.csv`

2. 整理访谈事实
   - 先抽取管理层明确陈述的内容。
   - 再用 BP、参考资料和公开信息补充背景。
   - 对同一事项出现不同口径时，写出差异并列为待核实。

3. 公开信息核验
   - 可查企业官网、工商公示/企查查类数据库、国家知识产权局、信用中国、裁判文书、政府/协会/榜单、上市公司公告、招投标/采购、权威行业报告、新闻报道等。
   - 优先使用官方、监管、公告、客户披露、专利局、法院/信用平台、榜单主办方等可追溯来源。

4. 撰写纪要
   - 语气使用正式访谈纪要风格，避免营销化。
   - 对管理层陈述可写“据公司管理层介绍”；对公开核验可写“公开资料显示”；对推断可写“基于上述信息初步判断”。
   - 每个字段至少有一个来源编号。

5. 生成文档
   - 先形成结构化 JSON，再运行 `scripts/build_interview_minutes.py`。
   - 生成后检查正文、字段来源标注和来源清单是否完整。

## 使用脚本

生成空白带来源附录的模板：

```bash
python3 scripts/build_interview_minutes.py --output /path/to/项目_管理层访谈纪要.docx
```

用 JSON 填充：

```bash
python3 scripts/build_interview_minutes.py \
  --answers /path/to/answers.json \
  --output /path/to/项目_管理层访谈纪要.docx
```

`answers.json` 示例：

```json
{
  "project_name": "示例科技",
  "company_short_name": "示例科技",
  "fields": {
    "M001": {
      "value": "示例科技项目管理层访谈纪要",
      "sources": ["[S1] 现场访谈记录 2026-05-25"],
      "evidence_level": "C-访谈记录",
      "quote_or_link": "访谈记录标题",
      "to_verify": ""
    },
    "M008": {
      "value": "据公司管理层介绍，公司成立于 2020 年，核心团队来自半导体设备及工艺领域，创始人曾负责相关产品量产导入。",
      "sources": ["[S1] 现场访谈记录 2026-05-25", "[S2] BP p.4"],
      "evidence_level": "C-公司材料/访谈记录",
      "quote_or_link": "BP p.4；访谈记录第 12-18 分钟",
      "to_verify": "需补充核心团队履历证明和工商历史沿革"
    }
  },
  "sources": [
    {"id": "S1", "type": "现场访谈记录", "citation": "《示例科技现场访谈记录》，2026-05-25，用户提供"},
    {"id": "S2", "type": "BP/公司材料", "citation": "《示例科技BP》，用户提供，p.4"}
  ]
}
```

## 资源

- `assets/附件1：项目管理层访谈纪要.docx`：原始 Word 模板。
- `references/field-map.csv`：字段 ID、模板定位文本、字段名和填写提示。
- `references/fill-guidance.md`：纪要撰写口径、来源标注、证据等级和核验清单。
- `scripts/build_interview_minutes.py`：根据 JSON 生成带来源标注的 Word 纪要。

## 注意事项

- 若用户提供的是原始转写稿，不要机械逐字整理，要按模板章节重组。
- 若访谈中没有覆盖某章节，可用 BP/公开信息补充，但必须标注来源并说明 `非现场访谈确认`。
- 若企业存在处罚、诉讼、舆情或财务异常，必须写入“重大事项”或“其他需要关注的事项”，不得省略。
- 若用户同时需要前置研判表，可联动使用 `project-preliminary-assessment-form`。
